# Evals

This folder holds the evaluation method and the code that runs it. `evals/results/RESULTS.md` is generated by `evals/report.py` from raw outputs and is never edited by hand. `evals/ERROR_ANALYSIS.md` is written by a person after reading the failures. Neither exists until a run has produced them.

## Dataset

- 50 or more real photos of ingredient labels in `evals/labels/`, including hard cases (curved packs, glare, small print, Hindi or other scripts, dark backgrounds). Use `LABEL_CHECKLIST.md`.
- One ground-truth file per photo, `evals/labels/<id>.json`, next to `<id>.jpg` (or `.jpeg`, `.png`, `.webp`). The ground truth is transcribed from the photo and **reviewed by a person**, whose name goes in `reviewed_by`. Files without a reviewer are excluded and counted in the report.
- Open Food Facts images, if used, are attributed, marked `"source": "open_food_facts"`, and their ground truth is also reviewed, not copied.

```json
{
  "id": "lbl_001",
  "source": "photographed",
  "ingredients_text": "exact ingredient text as printed on the label",
  "ingredients": ["canonical ingredient names in label order"],
  "allergen_groups": ["peanuts", "soy"],
  "reviewed_by": "name of the person who checked this file",
  "notes": "glare on the right third"
}
```

`allergen_groups` uses exactly the groups of the on-device scanner: `tree nuts`, `peanuts`, `lactose`, `gluten`, `soy`, `shellfish`, `eggs`. It lists which groups are present in the ingredients. The loader rejects any other value.

## Metrics (defined before measuring)

| Metric | Definition | Produced by |
|---|---|---|
| OCR error rate | Character and word error rate of extracted text vs. `ingredients_text`, for cloud OCR and for on-device ML Kit. | `run_cloud.py` (cloud); a device export `mlkit_ocr.json` (on device) |
| Ingredient parsing | Precision and recall of the parser's ingredient list vs. `ingredients`, given the ground-truth text. This is the re-measurement of the resume's "data-mapping accuracy". It reports whatever it finds. | `flutter test test/eval` |
| Allergen detection | Per group and overall: true/false positives and negatives, precision and recall. **Every missed allergen (false negative) is listed individually.** | `flutter test test/eval` |
| Citation correctness | For each cited statement a person marks `supported` or `not_supported` in `results/raw/citation_review.csv`. | `run_cloud.py` writes the sheet; a person fills it |
| Latency | p50 and p95 per endpoint, with the number of runs and a note on warm or cold instance. | `run_cloud.py` |
| Cost per scan | Mean tokens per call times current published prices, which the operator supplies with a date. | `report.py` |

## How to run

```bash
# 1. On-device engine (writes results/raw/local_engine.json)
flutter test test/eval

# 2. Cloud path (needs a deployed service and a current Firebase ID token)
NUTRILENS_ID_TOKEN=... python evals/run_cloud.py --base-url https://SERVICE_URL --repeats 3 --note "warm instance"

# 3. A person fills the `verdict` column in results/raw/citation_review.csv

# 4. Generate the report
python evals/report.py --price-in <per-million input> --price-out <per-million output> --price-date <YYYY-MM-DD>
```

Cold-start latency needs a separate run against an instance that has been idle, with `--note "cold start"`.

## Rules

- No number goes into the README, the resume or a PR unless it comes from `RESULTS.md`.
- Each report records the git commit, date, model names and label counts.
- If a result is worse than the resume, the resume changes (see `RESUME_FACTS.md`).
